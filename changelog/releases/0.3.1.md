**Paste a Google AI answer into Obsidian and get clean, stable footnotes again. Google changed how it cites sources; 0.3.1 reads the new format.**

> **Requires Obsidian 1.13 or later**, same as 0.3.0.

## Why care?

Cite Wide's **Paste LLM content** command turns an AI answer's numbered citations into stable `[^hex]` footnotes, with each source defined underneath. Google recently stopped putting a source list at the end of its AI answers. Instead, every sentence ends with its own links, numbered from 1 each time. Pastes started arriving as raw brackets and URLs, with every citation flagged as missing its source. This release fixes that.

## What's new

- **Google AI's new citation style converts to footnotes.** `[1] (https://…), [2] (https://…)` after a sentence becomes `[^a1b2c3] [^d4e5f6]`, with one definition per source.
- **One source, one footnote.** Google repeats the same link under different numbers across sentences. Cite Wide recognizes the URL and uses one ID for it everywhere.
- **Google's `•` bullets become markdown lists**, so they render as lists.
- **Both commands handle it:** *Paste LLM content*, and *Parse LLM citations* on a note you've already pasted into.

Google's new format carries no page titles, so new footnotes start as the bare URL. Run **Enrich citations** afterward to fill in titles, authors, and publishers.

## Under the hood

- A pre-pass, `normalizeInlineUrlCitations`, rewrites each citation group into the numeric form the existing parser already handles: an inline `[n1, n2]` plus one `[n] [url](url)` definition per distinct URL. The conversion pipeline itself is unchanged.
- New numbers start above any `[N]` already present, so old- and new-format text in one paste can't collide. Text without the new groups passes through untouched.
- **Tests:** 121 (4 new, built from a real Gemini paste).
- **Version** 0.3.0 → 0.3.1 across `manifest.json`, `package.json`, and `versions.json`. Every release asset is attested: `gh attestation verify main.js --repo lossless-group/cite-wide`.
