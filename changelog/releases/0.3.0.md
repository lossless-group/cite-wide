**Cite Wide turns the citation chaos of LLM-pasted research into clean, stable, vault-wide references. Starting with 0.3.0, every setting is in Obsidian's settings search, and the plugin requires Obsidian 1.13 or later.**

## Why care?

Paste a Perplexity answer and a Google AI Overview into the same note and both will claim `[1]`. One definition overwrites the other, and the attribution quietly stops matching the source. Cite Wide gives every citation a stable hex identifier (`[^a1b2c3]`) that survives reordering, copy-paste, and merging. It dedupes citations that point at the same URL, converts LLM-pasted research into one canonical format, and can save each citation as its own file for Dataview or Bases queries.

Obsidian 1.13 added settings search, but it only finds settings from plugins built on its new declarative settings API. 0.3.0 moves Cite Wide onto that API, so you can type "Jina" or "citations folder" in Settings and go straight to the setting.

Open Obsidian → **Settings → Community plugins → Browse → "Cite Wide" → Install → Enable**.

## What 0.3.0 brings

- **Searchable settings.** The Jina.ai API key, citations folder, and auto-save toggle all appear in settings search. The API key status updates as you type, and the "How to use URL citation extraction" walkthrough is searchable too.
- **Promote to canonical source.** For the few sources worth keeping, a new command reads the footnote and the page's own metadata, lets you confirm the details, saves the PDF and the text as markdown into your vault, and writes a complete, reusable citation record.
- **A tab Obsidian draws itself.** Cite Wide describes its settings and Obsidian renders them, so they match the rest of Settings.
- **Sentence-case commands and buttons**, to match Obsidian's own UI. Command IDs are unchanged, so your hotkeys keep working.
- **Requires Obsidian 1.13 or later.** If you're on an older Obsidian, 0.2.3 remains available, and Obsidian installs the newest version compatible with your app.

## What it changes for users

**Installing or updating from inside Obsidian:** your settings carry over unchanged, because `data.json` keeps the same three keys. Commands keep the same IDs, so hotkeys stay bound.

**Looking for a setting:** open Settings and type into the search box. You don't need to open the Cite Wide tab first.

**Everything else:** citation conversion, dedupe, the save flow, URL extraction, and LLM-paste parsing behave the same as in 0.2.3.

## Under the hood

- The settings tab implements `getSettingDefinitions()` and no longer overrides `display()`. `getControlValue` / `setControlValue` bind the three settings and keep their side effects (the Jina key goes to the URL service, the folder to the citation-file service).
- Lint now runs [`eslint-plugin-obsidianmd`](https://github.com/obsidianmd/eslint-plugin), the rule set Obsidian's marketplace review bot enforces. It reports 0 errors and 0 warnings. To get there, inline modal styles moved into `styles.css`, network requests use `requestUrl`, and replaced citation files go through `fileManager.trashFile`, which respects your deletion preference.
- A first test suite (`pnpm test`, Node's built-in runner, no new dependencies) checks the settings definitions and confirms that `onload()` registers all 15 commands under a stub that mimics how Obsidian 1.14 registers settings tabs.
- `obsidian` types pinned to 1.13.1; `minAppVersion` 1.8.10 → 1.13.0; version 0.2.3 → 0.3.0 across `manifest.json`, `package.json`, and `versions.json`.
- Like 0.2.3, every release asset is cryptographically attested. Verify with `gh attestation verify main.js --repo lossless-group/cite-wide`.
